Frostfuscator 1.3.4 introduces a verification-focused SSA compiler layer for safer bytecode transformation, expands the obfuscation pipeline built on it, and gives the desktop application a consistent visual identity.

## Added

- Added the `frost-ir` module with typed SSA values, first-class control-flow and exception edges, edge-keyed phi nodes, validation, deterministic snapshots, text/DOT output, versioned serialization, and plugin extension contracts.
- Added JVM bytecode import and transactional lowering with source mappings, frame reconstruction, exception/debug metadata preservation, verification, and safe fallback when a method is unsupported or cannot be lowered.
- Added reusable graph and data-flow analyses including dominance, loops, liveness, sparse conditional constant propagation, global value numbering, symbolic expressions, MemorySSA, alias, escape, nullness, and integer ranges.
- Added SSA flow and phase-five passes for opaque predicates, flattening, exception/condition/switch rewriting, control-flow shuffling, copy weaving, expression outlining, string-key data flow, and thread interleaving.

## Improved

- Migrated optimization, flow, encryption, indirection, method-salting, and virtualization paths to bounded IR-backed transformations that publish bytecode only after successful validation and lowering.
- Expanded optimizer coverage with SSA constant/copy propagation, common-subexpression elimination, dead-code removal, critical-edge normalization, and bounded same-class private-static inlining.
- Added an `aggressive-inlining.max-ir-instructions` limit so IR-backed inlining can be capped independently of input and output bytecode limits.
- Documented Frost-IR's architecture, capability gates, module boundaries, and verification workflow, and refreshed the project README and visual previews.
- Applied the supplied high-resolution Frostfuscator artwork to the application window, taskbar, startup experience, and custom title bars.
- Used the solid icon where operating-system visibility matters and the transparent mark inside the interface for clean integration across themes.

## Fixed

- Ensured packaged GUI builds always report the current Frostfuscator version after a version change.
- Hardened transformer fallbacks so unsupported or unverifiable methods retain their original bytecode instead of receiving a partial rewrite.
- Bounded phase-five expression discovery before recursive expansion so shared SSA graphs cannot cause excessive verification or transformation time.
