# Frostfuscator 1.3.2

Frostfuscator 1.3.2 expands bytecode analysis, runtime extensibility, and modern Java compatibility while making large-project workflows more responsive and reliable.

## Added

- Added a complete graph analysis workbench for class dependencies, method calls, inheritance, packages, control flow, transformer pipelines, mappings, generated members, and completed build execution.
- Added focused, searchable Cytoscape visualizations with direction and depth controls, semantic filters, multiple layouts, metadata inspection, comparison summaries, and PNG export.
- Added deterministic Mermaid, JSON, and DOT graph exports through both the desktop application and headless CLI.
- Added public graph extension APIs so plugins can contribute builders, metadata, filters, context actions, and export formats without depending on the GUI renderer.
- Added runtime plugin management in the GUI, including loading, reloading, unloading, and rescanning plugin JARs without restarting Frostfuscator.
- Added `PRE_RENAME` and `POST_FLOW` plugin execution hooks with stable custom ordering weights.
- Added automatic discovery and version reporting for Clang, GCC/MinGW, MSVC, and Zig toolchains, including a native Zig C++ backend.
- Added fine-grained transformation progress reporting and completed-build graph snapshots.
- Added application-data path management and diagnostic log handling for cleaner packaged desktop deployments.

## Improved

- Improved large-project graph performance with reusable bytecode indexes, scoped projections, deterministic caching, cancellable background work, configurable safety limits, and aggressive resource release when the graph page closes.
- Improved the bytecode editor with structured instruction targeting so edits reliably update the intended constant instruction.
- Improved decompiler responsiveness by cancelling obsolete work when users switch classes rapidly.
- Improved transformer throughput with per-class progress callbacks and more efficient priority-aware event listener insertion.
- Improved the Reports page in compact-density mode and expanded GUI status feedback for plugins, graph tasks, native toolchains, and long-running builds.
- Improved the startup and application shell experience, search controls, navigation, icon assets, and packaged desktop presentation.
- Improved nested and fat-JAR processing with safer archive lifecycle management and more reliable repacking.
- Improved CLI graph workflows with focused traversal, graph limits, library inclusion, pipeline previews, and completed-build exports.

## Changed

- Structural control-flow transformations now mark affected classes for full stack-map frame recomputation using hierarchy-aware type resolution.
- The virtualization runtime now models JVM category-2 operands explicitly, enabling legal `long` and `double` duplication and stack-manipulation forms.
- Plugin lifecycle ownership now includes transformer deregistration, event-listener cleanup, disable/unload callbacks, and classloader closure.
- Transformer ordering is now stable within each execution pass and can be customized by third-party plugins.
- Native compiler selection now considers Zig alongside Clang, GCC, and MSVC and reports attempted toolchains when compilation cannot complete.

## Fixed

- Fixed verification failures caused by stale or stripped `StackMapTable` frames in heavily transformed classes and nested JARs.
- Fixed sealed-class permitted-subclass and record-component remapping for Java 17 and Java 21 bytecode.
- Fixed record field/accessor rename synchronization so reflective record access remains valid.
- Fixed reflective class and field references being renamed despite preservation analysis.
- Fixed plugin metadata updates by using structured YAML processing for non-standard formatting, comments, and nested descriptors.
- Fixed multi-release JAR runtime loading so versioned class entries resolve correctly on supported JVMs.
- Fixed `long` and `double` operand corruption across `POP2`, `DUP*`, arithmetic, conversion, array, invocation, and return operations in FrostVM.
- Fixed Windows plugin JAR handle retention after unload or reload.
- Fixed graph UI stalls on oversized methods by enforcing configurable instruction and graph pruning thresholds.

## Security

- Strengthened transformed-bytecode verification across complex control-flow, switch, opaque-predicate, and exception-flow protections.
- Hardened embedded graph rendering with a bundled offline renderer, restrictive content security policy, no network access, and no Java object bridge.
- Improved native protection setup validation by detecting usable local toolchains before compilation begins.
- Improved archive and runtime compatibility checks to reduce invalid protected outputs reaching deployment.
